# CargoFlow: Roadmap

## This prototype: prove the workflow

- Departure dashboard, at-risk reasons and Space Ledger
- AI reads replies; a person approves every action
- Freed space offered to waiting requests after rule checks
- Rough revenue estimate

## Next scope: make it plannable, with a pilot on one route

- As a controller, I can move a booked shipment to another flight, with the forwarder's agreement.
- As a load planner, I see pallet sizes, positions and weight limits before an offer goes out.
- As a capacity manager, I see chargeable weight, allotments, connections and priority cargo.
- As an airline, I connect a read-only booking feed and shared mailbox, and keep a permanent audit trail.

## The scope after that: make it network-wide

- As a network controller, I rebalance space across stations, freighters and passenger belly hold.
- As a revenue manager, I use the airline's own show-up predictions to decide who to ask first.
- As a forwarder, I confirm, reduce or accept an offer myself in a portal.
- As an airline, I can allow low-risk approvals to run automatically, only after the evidence supports it.

## Possible later

Passenger disruption recovery could use a similar approach, but it would be a separate product.

## What would change this plan

- A capacity controller says the problem or workflow is different.
- An existing product already closes the loop.
- Too little freed space can be resold in time.
